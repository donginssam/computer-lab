# 0과 1로 수 나타내기: 자릿값과 2로 나누기

[문서 목록](../README.md) · [시뮬레이터](../../src/simulators/binary-number/index.tsx)

이 문서는 데이터 단원의 이진수 시뮬레이터를 위한 교사용 참고 자료입니다. 학생 화면에서는 카드와 나눗셈처럼 눈으로 확인할 수 있는 과정을 먼저 보여 주고, 이 문서에서는 그 과정이 맞는 이유와 구현 범위를 정리합니다.

## 구성과 학습 흐름

| 탭          | 수준 | 핵심 질문                                  | 활동                                            |
| ----------- | ---- | ------------------------------------------ | ----------------------------------------------- |
| 자릿값 카드 | 핵심 | 왜 자리마다 2배가 될까?                    | 128·64·…·1 카드 8장을 켜고 꺼서 목표 수 만들기  |
| 2로 나누기  | 핵심 | 교과서 계산법은 왜 나머지를 거꾸로 읽을까? | 몫이 0이 될 때까지 한 단계씩 나누고 나머지 읽기 |

다루는 수는 **양의 정수(0 포함)** 입니다. 두 탭 모두 **8비트**를 고정해 쓰며, 화면에서는 "0이나 1이 들어가는 한 칸을 비트라고 한다"고 한 번 설명합니다.

음의 정수(부호 비트, 2의 보수)는 한때 `생각 열기` 탭으로 두었다가 뺐습니다. 정보 교과 편성 학년을 고려하면 고등학교에서 다루는 편이 안전하다고 판단했습니다.

## 자릿값 카드

십진수는 한 자리에 0~9를 쓰므로 자리가 하나 올라갈 때마다 10배가 되고, 이진수는 한 자리에 0과 1만 쓰므로 2배가 됩니다. 8비트의 자릿값은 다음과 같습니다.

```text
128  64  32  16   8   4   2   1
```

8장을 모두 켜면 `128 + 64 + … + 1 = 255`이므로 8비트는 0~255, 곧 `2⁸ = 256`가지 수를 나타냅니다.

### 왜 한 가지로만 만들어지는가

자릿값 `2ᵏ`는 그보다 작은 자릿값을 모두 더한 값보다 정확히 1 큽니다.

```text
2ᵏ = (2ᵏ⁻¹ + 2ᵏ⁻² + … + 1) + 1
```

그래서 어떤 수를 만들 때 큰 카드부터 "남은 수보다 크지 않으면 켠다"를 반복하면 항상 성공하고, 그 방법이 유일합니다. 큰 카드를 켜야 할 때 켜지 않으면 작은 카드를 모두 켜도 모자라기 때문입니다.

이는 [문제 해결 전략 실험실](problem-solving.md)의 **욕심쟁이 방법**과 같은 규칙입니다. 이진 자릿값은 욕심쟁이 방법이 항상 맞는 "동전 종류"의 예이므로, 두 시뮬레이터를 이어서 다루면 실험용 동전 A·B와 대비할 수 있습니다. 화면의 안내 문구("큰 카드부터 켤지 말지 정해 보세요")도 이 순서를 권합니다.

## 2로 나누기

어떤 수 `n`을 2로 나누면 `n = 2q + r`(`r`은 0 또는 1)입니다. `r`은 `n`이 짝수인지 홀수인지, 곧 **1의 자리 비트**입니다. 몫 `q`는 `n`의 이진수에서 1의 자리를 지운 수이므로, `q`를 다시 2로 나눈 나머지는 2의 자리 비트가 됩니다. 이를 몫이 0이 될 때까지 반복하면 비트가 **작은 자리부터** 나오므로, 이진수를 쓸 때는 나머지를 아래에서 위로 읽습니다.

```text
2 ) 13 … 1   ← 1의 자리
2 )  6 … 0
2 )  3 … 1
2 )  1 … 1   ← 가장 큰 자리
     0
아래에서 위로: 1101
```

자릿값 카드는 큰 자리부터, 2로 나누기는 작은 자리부터 비트를 정합니다. 방향은 반대지만 같은 수에 대해 항상 같은 결과가 나오며, 엔진 테스트가 1~255 전체에서 이를 확인합니다. 완료 화면의 `자릿값 카드로 확인하기`는 같은 수를 목표로 카드 탭을 열어 두 방법을 연결합니다.

화면은 한국 교과서에서 쓰는 거꾸로 된 나눗셈(단나눗셈) 모양을 따르며, 단계 수는 나눗셈 줄 수에 "나머지를 거꾸로 읽기" 한 단계를 더한 값입니다. `n`의 이진수가 `k`자리면 나눗셈은 정확히 `k`번입니다. 0은 나눌 필요가 없으므로 이 탭의 입력 범위는 1~255입니다.

### 주소 값

| 파라미터 | 뜻               | 범위  | 기본값  |
| -------- | ---------------- | ----- | ------- |
| `tab`    | `cards`·`divide` | —     | `cards` |
| `n`      | 카드로 만들 수   | 0~255 | 13      |
| `d`      | 2로 나눌 수      | 1~255 | 13      |

값이 없거나 숫자가 아니면 기본값을, 범위를 벗어나면 가까운 경계를 씁니다(공용 `clampedParam`).

화면의 입력칸([NumberField.tsx](../../src/simulators/binary-number/NumberField.tsx))은 입력하는 동안 아무것도 막지 않습니다. 칸을 벗어나거나 Enter로 확정할 때 범위 안의 정수로 바꾸고, 바꾼 이유를 입력칸 아래에 경고로 보여 줍니다. 255보다 큰 수는 255로("입력한 수(999)가 너무 커서 255로 바꿨습니다"), 음수는 최솟값으로("음수는 쓸 수 없어서 0으로 바꿨습니다"), 2로 나누기의 0은 1로, 소수는 소수점 아래를 버립니다. 경고는 다시 입력을 시작하거나 무작위 수 등으로 값이 바뀌면 사라집니다. 값이 바뀌어도 설정 칸을 새로 만들지 않고 카드와 나누기 진행만 초기화하므로, 확정과 동시에 경고가 사라지지 않습니다.
