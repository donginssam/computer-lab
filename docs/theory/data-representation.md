# 문자·그림·소리를 0과 1로: 데이터 표현

[문서 목록](../README.md) · [문자](../../src/simulators/text-encoding/index.tsx) · [그림](../../src/simulators/image-pixel/index.tsx) · [소리](../../src/simulators/sound-digitize/index.tsx)

데이터 단원의 [이진수 시뮬레이터](binary-number.md) 뒤에 이어지는 세 시뮬레이터의 교사용 참고 자료입니다. 세 시뮬레이터 모두 "정보를 수로 약속하고, 그 수를 이진수로 적는다"는 한 가지 생각을 문자·그림·소리에 적용합니다.

| 시뮬레이터          | 탭·단계                                     | 핵심 질문                                    |
| ------------------- | ------------------------------------------- | -------------------------------------------- |
| 문자를 0과 1로      | 문자 → 이진수, 이진수 → 문자                | 글자는 어떤 약속(코드표)으로 수가 될까?      |
| 그림을 픽셀과 RGB로 | RGB로 색 만들기, 픽셀 그림                  | 색 하나, 그림 한 장은 몇 비트일까?           |
| 소리를 0과 1로      | 원래 소리 → 표본화 → 양자화 → 부호화 → 복원 | 이어진 소리를 어떻게 셀 수 있는 수로 바꿀까? |

## 문자

- ASCII는 0~127, 곧 7비트 코드표입니다. 화면에서는 1바이트(8비트)로 맞춰 맨 앞에 0을 붙여 보여 주고, 128 이상을 켜면 "ASCII 밖"이라고 알립니다.
- 코드표는 앞 4비트를 줄, 뒤 4비트를 칸으로 둔 16열 표입니다. 0~31(제어 문자)은 모양이 없어 표에서 빼고, 비트 토글로 만들면 이름(NUL, LF 등)을 보여 줍니다.
- 대문자와 소문자는 32의 자리 비트 하나만 다릅니다(`A` 0100 0001, `a` 0110 0001). 전용 버튼과 엔진 테스트가 이를 A~Z 전체에서 확인합니다.
- ASCII 밖 글자는 유니코드 번호와 UTF-8 바이트를 함께 보여 줍니다. 한글 음절은 U+AC00~U+D7A3이라 UTF-8로 3바이트입니다(`안` = `EC 95 88`). UTF-8의 바이트 나누기 규칙은 다루지 않고 "여러 바이트에 나눠 담는다"까지만 설명합니다.
- 입력은 코드 포인트 단위로 세며(이모지 한 개 = 한 글자), 표가 길어지지 않게 12글자까지만 바꿉니다.
- `숨은 낱말 읽기`는 ASCII 대문자 낱말의 바이트를 보여 주고 학생이 읽은 답을 대소문자 구분 없이 확인합니다.

## 그림

- 색은 R·G·B 세기를 각 0~255(8비트)로 적는 24비트 색입니다. 16진수 한 자리는 4비트이므로 채널 하나가 두 자리, 색 하나가 `#RRGGBB` 여섯 자리입니다.
- 16진수 입력은 `#` 유무와 세 자리 줄임(`#f80` → `#FF8800`)을 받아들이고, 읽을 수 없으면 값을 바꾸지 않고 알려 줍니다.
- 픽셀 그림은 8×8입니다. 용량 = 픽셀 수 × 색 깊이이며 24비트 색은 1,536비트(192바이트), 흑백 1비트는 64비트(8바이트)입니다.
- 흑백으로 바꿀 때는 밝기 `0.299R + 0.587G + 0.114B`(ITU-R BT.601)가 128 이상이면 1(하양)로 봅니다. 그래서 빨강(76)은 검정, 노랑(226)은 하양이 됩니다. 색 정보를 버린 결과가 원래 그림과 달라지는 것도 관찰 대상입니다.
- 흑백에서는 한 줄 8픽셀이 곧 1바이트라 `저장되는 값`을 줄마다 8비트로 보여 줍니다.

## 소리

교과서 순서대로 **표본화 → 양자화 → 부호화**입니다.

1. 표본화: 그래프 한 구간을 표본 수(4~32)만큼 같은 간격으로 나누어 각 칸의 시작에서 높이를 잽니다.
2. 양자화: 높이 −1~1을 `2^비트` 단계 눈금으로 읽고(`(값 + 1) / 2 × (단계 수 − 1)`) 가장 가까운 정수 단계로 반올림합니다. 표본 목록의 `3.5 → 4`처럼 반올림 전후를 함께 보여 줍니다.
3. 부호화: 단계 번호를 양자화 비트 수만큼의 이진수로 적습니다. 데이터 크기 = 표본 수 × 양자화 비트입니다.
4. 다시 소리로: 다음 표본까지 같은 높이를 유지하는 계단(sample-and-hold)으로 복원하고, 원래 파형과의 평균 절대 차이를 높이 범위(2)에 대한 백분율로 보여 줍니다.

설정을 바꿔도 진행 단계는 유지해, 같은 단계에서 표본 수·비트 수의 효과를 바로 비교하게 했습니다. 엔진 테스트는 두 파형 모두에서 표본 수나 비트를 늘리면 차이가 줄어드는지 확인합니다.

`들어 보기`는 Web Audio API로 그래프 한 구간을 1초에 110번 되풀이한 1.2초 소리를 만듭니다(구간에 파형이 두 번 있어 기본음 220Hz). 원래 소리와 복원한 계단 소리를 같은 방식으로 만들어 귀로 비교합니다. `AudioContext`가 없는 환경에서는 버튼을 숨깁니다. 실제 표본화 빈도(예: CD의 44.1kHz)와 나이퀴스트 조건은 개념 카드에서 "자주 잴수록 빠른 변화를 담는다" 수준으로만 다룹니다.

세 시뮬레이터 모두 결과가 입력만으로 정해지므로 기록과 저장소를 두지 않습니다. 주소에는 탭과 설정(입력 글자, 코드, 색, 색 깊이, 표본 수, 비트, 파형)만 남기고, 칠한 픽셀 그림·해독 문제·진행 단계는 남기지 않습니다.
