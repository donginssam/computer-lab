# 양팔저울로 이해하는 순차 탐색과 분할 정복

[문서 목록](../README.md) · [화면 규칙](../ui-guidelines.md)

이 문서는 교사가 양팔저울 시뮬레이터의 원리를 이해하고 학생에게 알고리즘의 효율 차이를 설명할 때 참고하는 자료입니다. 화면의 **‘차례로 비교하기’는 순차 탐색**, **‘절반씩 나누기’는 분할 정복의 원리를 활용한 탐색**에 대응합니다. 두 방법이 한 번의 저울질로 후보를 얼마나 줄이는지에 초점을 맞춥니다.

## 문제의 조건과 비교 기준

겉모양이 같은 동전 N개 중 **진짜보다 가벼운 가짜 동전이 정확히 하나** 있습니다. 양팔저울에 같은 수의 동전을 올리면 ‘왼쪽이 가볍다’, ‘오른쪽이 가볍다’, ‘양쪽이 같다’ 중 하나를 알 수 있습니다. 이 결과를 이용해 가짜일 수 있는 동전, 즉 **후보**를 줄여 갑니다.

효율을 비교하는 기준은 **가짜 동전을 확정할 때까지 필요한 저울질 횟수**입니다. 동전을 옮기는 시간, 화면 애니메이션 시간, 프로그램 내부의 배열 처리 시간은 이 횟수에 포함하지 않습니다. 아래 `O(N)`과 `O(log N)`도 이 문제에서 저울질 횟수가 증가하는 양상을 나타냅니다.

| 화면 이름       | 연결할 알고리즘 개념 | 후보를 줄이는 방식                         | 정확한 최악 저울질 횟수 | 증가 양상  |
| --------------- | -------------------- | ------------------------------------------ | ----------------------- | ---------- |
| 차례로 비교하기 | **순차 탐색**        | 앞에서부터 두 개씩 확인하고 제외           | `⌊N/2⌋`                 | `O(N)`     |
| 절반씩 나누기   | **분할 정복**        | 후보를 나누고 가짜가 있는 묶음만 계속 탐색 | `⌊log₂N⌋`               | `O(log N)` |

`⌊x⌋`는 x 이하의 가장 큰 정수입니다. 수식은 교사용 설명이며 학생에게는 후보가 줄어드는 과정과 실제 횟수로 먼저 제시할 수 있습니다.

## 차례로 비교하기: 순차 탐색

순차 탐색은 대상을 앞에서부터 차례로 확인해 원하는 것을 찾는 방법입니다. 이 시뮬레이터에서는 저울의 특성을 이용해 **동전 두 개를 한 쌍씩 확인하는 순차 탐색**으로 구현했습니다.

1. 첫 번째와 두 번째 후보를 저울 양쪽에 하나씩 올립니다.
2. 기울면 가벼운 쪽 동전이 가짜이므로 종료합니다.
3. 양쪽이 같으면 두 동전은 진짜이므로 제외하고 다음 두 후보를 확인합니다.
4. 후보가 한 개만 남으면 추가 저울질 없이 그 동전을 가짜로 확정합니다.

일반적인 목록의 순차 탐색은 원소를 하나씩 검사합니다. 여기서는 한 번에 두 개를 확인하므로 정확한 최악 횟수는 N회가 아니라 `⌊N/2⌋`회입니다. 하지만 매번 줄이는 후보 수가 일정하므로 전체 동전 수에 비례해 저울질이 늘어난다는 **선형적인 증가 특성**은 같습니다.

예를 들어 동전 8개 중 8번이 가짜라면 `(1, 2) → (3, 4) → (5, 6) → (7, 8)` 순서로 4회 저울질합니다. 동전 수가 16개, 32개로 늘어나면 최악 횟수도 8회, 16회로 늘어납니다.

## 절반씩 나누기: 분할 정복

분할 정복은 큰 문제를 작은 문제로 나누어 해결하는 설계 방법입니다. 이 시뮬레이터에서는 **전체 후보에서 가짜 동전을 찾는 문제를, 가짜가 포함된 작은 묶음에서 찾는 문제로 바꾸는 과정**을 반복합니다.

1. 후보를 같은 크기의 두 묶음으로 나눠 양쪽에 올립니다. 홀수라면 한 개는 저울 밖에 둡니다.
2. 기울면 가벼운 쪽 묶음에 가짜 동전이 있으므로 그 묶음만 후보로 남깁니다.
3. 양쪽이 같으면 저울 밖에 둔 한 개가 가짜 동전이므로 종료합니다.
4. 남은 후보에 같은 방법을 반복하고, 한 개가 되면 종료합니다.

가짜 동전이 포함될 수 없는 묶음을 통째로 제외하기 때문에, 탐색을 계속할 때마다 후보가 절반 이하로 줄어듭니다. 동전 8개 중 8번이 가짜인 경우 후보 수는 `8 → 4 → 2 → 1`로 줄어 총 3회가 필요합니다.

여기서 사용하는 분할 정복은 **나눈 문제 중 필요한 한쪽만 계속 해결하는 형태**입니다. 병합 정렬처럼 양쪽 문제를 모두 해결한 뒤 결과를 합치는 과정은 없습니다. 엄밀하게 세분하면 문제 크기를 줄여 한 하위 문제만 푸는 ‘감소 정복’으로도 분류할 수 있으므로, 수업에서는 “나누고, 필요한 부분을 선택하고, 같은 절차를 반복한다”는 구조를 설명하면 좋습니다.

이진 탐색과도 후보를 절반씩 줄인다는 점이 닮았습니다. 다만 이진 탐색은 정렬된 자료에서 중간값과의 대소 비교로 탐색 범위를 선택하는 반면, 이 실험은 동전 묶음의 무게 차이로 선택합니다. 동전 번호나 무게를 미리 정렬할 필요는 없습니다.

## 왜 횟수 차이가 커지는가?

순차 탐색은 저울질 한 번으로 후보를 **두 개씩** 제외합니다. 분할 정복 방식은 탐색이 계속될 때 후보를 **절반씩** 줄입니다. 동전 수가 커질수록 이 차이가 누적됩니다.

| 동전 수 N | 순차 탐색의 최악 횟수 | 분할 정복 방식의 최악 횟수 |
| --------- | --------------------- | -------------------------- |
| 8         | 4                     | 3                          |
| 16        | 8                     | 4                          |
| 32        | 16                    | 5                          |
| 64        | 32                    | 6                          |
| 100       | 50                    | 6                          |

2의 거듭제곱인 동전 수를 두 배로 늘려 보면 순차 탐색의 최악 횟수는 두 배, 분할 정복 방식의 최악 횟수는 한 번 증가합니다. `O(N)`과 `O(log N)`은 이러한 증가 양상을 나타내며, 특정 실험에서 반드시 그 횟수가 나온다는 뜻은 아닙니다.

### 절반씩 나누기의 최악 횟수가 내림인 이유

현재 알고리즘은 후보가 홀수일 때 한 개를 저울 밖에 두고, 탐색이 계속되는 경우에는 `floor(후보 수 / 2)`개를 남깁니다. N=7의 최악 경로는 `7 → 3 → 1`이므로 2회입니다. 따라서 이 구현의 정확한 최악 횟수는 `⌊log₂N⌋`입니다.

`⌈log₂N⌉`도 상한으로 사용할 수 있지만 실제 최악 횟수보다 클 수 있습니다. 예를 들어 N=100에서 내림값은 6, 올림값은 7입니다. 현재 화면의 ‘가장 많이 걸려도’와 그래프는 정확한 최악 횟수인 6을 사용합니다.

## 실험 결과를 읽을 때 구분할 점

### 같은 위치에서의 비교와 각 방법의 최악 횟수

단일 시뮬레이션에서 ‘가장 늦게 찾는 곳’을 선택하면 **선택한 알고리즘 기준**의 최악 위치에 가짜 동전을 둡니다. 나란히 비교에서는 **순차 탐색 기준**의 최악 위치를 정한 다음, 두 방법에 같은 위치를 사용합니다.

따라서 나란히 비교의 두 결과가 각각의 최악 횟수와 모두 같을 필요는 없습니다. N=100에서는 100번 동전을 가짜로 두어 순차 탐색은 50회, 분할 정복 방식은 3회에 찾습니다. 분할 정복 방식의 최악 횟수 6회보다 적게 나온 것은 오류가 아니라 **그 위치에서 일찍 찾았기 때문**입니다.

가장 늦게 찾는 위치도 항상 맨 끝은 아닙니다. 화면 번호로 N=7의 순차 탐색 기준은 6번, N=100의 분할 정복 기준은 98번입니다. 무작위 배치에서는 위치에 따라 횟수가 달라질 수 있으므로 한 번의 결과만으로 일반적인 효율을 단정하지 않습니다.

### 양쪽이 같아도 정보를 얻는다

N=7에서 세 개씩 양쪽에 올렸는데 무게가 같다면, 저울 밖의 한 개가 가짜입니다. ‘양쪽이 같다’는 결과도 후보를 줄이는 근거입니다. 이는 **가짜가 정확히 하나이며 진짜보다 가볍다**는 문제 조건 때문에 가능합니다. 가짜의 수나 무게 조건이 바뀌면 같은 추론을 그대로 사용할 수 없습니다.

### 절반씩 나누기가 가능한 최적 전략의 전부는 아니다

저울에는 세 가지 결과가 있으므로 후보를 세 묶음으로 나누는 전략도 생각할 수 있습니다. 이 문제 조건에서 최적 전략의 보장 횟수는 `⌈log₃N⌉`이며, 현재 구현된 절반씩 나누기의 횟수와 구분해야 합니다. 예를 들어 N=9는 세 개씩 세 묶음으로 나누면 최대 2회에 찾을 수 있지만, 현재 절반씩 나누기는 최대 3회입니다.

현재 시뮬레이터의 비교 대상은 순차 탐색과 절반씩 나누는 분할 정복 방식입니다. 3등분 비교 엔진은 제공하지 않습니다.

## 설명을 확인하는 질문

- **동전 수가 두 배가 되면 왜 두 방법의 횟수가 다르게 늘어날까?** 한 번에 제외하는 후보 수가 일정한지, 남기는 후보의 비율이 일정한지 설명하도록 합니다.
- **양쪽 무게가 같으면 아무것도 알아내지 못한 것일까?** 저울 위 동전과 밖의 동전 중 어디에 가짜가 있을 수 있는지 문제 조건으로 추론하도록 합니다.
- **100개 실험에서 절반씩 나누기가 3회에 끝났다면 항상 3회면 충분할까?** 이번 위치의 실제 횟수와 모든 위치를 고려한 최악 횟수를 구분하도록 합니다.

## 부록: 구현과 데이터 구조

아래는 동작 확인이나 유지보수가 필요할 때 참고하는 코드 설명입니다. 수업에서 알고리즘을 설명할 때는 앞의 후보 변화와 저울질 횟수를 중심으로 활용하면 됩니다.

### 엔진 계약

내부 `CoinId`와 `fakeIndex`는 0부터 시작하고 화면 번호는 1을 더합니다.

[engine/types.ts](../../src/simulators/balance-scale/engine/types.ts)의 `Algorithm`은 `id`, `name`, `shortName`, `bigO`, `bigOPlain`, `maxComparisons`, `worstCaseFakeIndex`, `init`, `step`을 제공합니다. `SimState`는 전체 수·가짜 위치·후보·비교 횟수·저울질 이력·종료 여부·답·커서를 보관합니다.

[core.ts](../../src/simulators/balance-scale/engine/core.ts)의 역할:

- `init(n, fakeIndex)`: 정수 N=2~100, 범위 내 정수 위치를 검증하고 초기 상태를 만듭니다.
- `tilt(left, right, fakeIndex)`: 양쪽 동전 수가 다르면 오류를 냅니다. 가짜 동전이 왼쪽이면 `left`, 오른쪽이면 `right`, 밖에 있으면 `balanced`입니다.
- `weigh(...)`: 한 번의 저울질을 이력에 추가하고 결과에 맞는 후보만 남깁니다. 후보가 하나면 같은 단계에서 답을 확정합니다.

배열의 중복·교집합 같은 임의 배치는 `tilt`에서 검증하지 않습니다. 현재 두 엔진이 유효한 후보 분할을 만들어 호출한다는 전제입니다. 직접 배치 기능을 도입한다면 별도의 배치 검증이 필요합니다.

### 알고리즘과 위치 선택

[engine/index.ts](../../src/simulators/balance-scale/engine/index.ts)의 `sequential-pair`는 순차 탐색, `divide-half`는 절반씩 나누는 분할 정복 방식입니다. 두 `step`은 입력을 변경하지 않으며, 종료 상태에서는 같은 객체를 반환합니다. 순차 알고리즘의 `cursor`는 2씩 증가하지만 다음 짝은 `candidates`에서 선택합니다.

[worstCase.ts](../../src/simulators/balance-scale/engine/worstCase.ts)는 순차 최악 위치를 짝수 N에서 `n-1`, 홀수 N에서 `n-2`로 정합니다. 절반 나누기는 오른쪽 절반을 계속 따라가는 위치를 계산합니다.

[useSimulation.ts](../../src/simulators/balance-scale/state/useSimulation.ts)의 `chooseFake`는 단일 모드에서 선택한 알고리즘의 최악 위치를 사용합니다. 나란히 비교는 `WORST_CASE_BASELINE = "sequential-pair"`로 고정하고, 무작위 옵션은 `Math.floor(Math.random() * n)`으로 위치를 선택합니다.

### 실행 상태와 생명주기

[state/reducer.ts](../../src/simulators/balance-scale/state/reducer.ts)의 `RunState`는 `options`, 두 알고리즘의 `pair`, `running`, `speed`, 공통 시간축 `tick`, `runId`를 가집니다.

| 액션 / 변화           | 동작                                                                    |
| --------------------- | ----------------------------------------------------------------------- |
| `step`                | 단일 알고리즘 또는 두 알고리즘을 한 단계 진행하고 모두 끝나면 자동 정지 |
| `back`                | 초기 상태부터 이전 tick까지 재실행해 복원, 자동 실행 정지               |
| `auto`                | 자동 실행 여부 설정                                                     |
| `speed`               | 실행 간격 변경                                                          |
| `reset`               | 새 가짜 위치와 runId로 초기화, 현재 속도 유지                           |
| 모드·N·위치 옵션 변경 | 페이지의 `Simulation` key 변경으로 재마운트, 새 실험 시작               |
| 알고리즘 변경         | 단일 모드에서는 재마운트, 비교 모드 key에는 포함하지 않음               |

자동 실행은 `useEffect`의 `setTimeout` 체인입니다. 정지·속도 변경·다음 tick·언마운트 시 이전 타이머를 정리합니다. 재마운트 시 속도는 기본 800ms로 돌아갑니다. 되감기는 기존 실험 기록을 지우지 않습니다.

### URL 설정

[index.tsx](../../src/simulators/balance-scale/index.tsx)에서 쿼리를 읽습니다.

| 쿼리        | 값 / 기본 동작                                                     |
| ----------- | ------------------------------------------------------------------ |
| `mode`      | `simulation`, `compare`, `records`; 그 외는 `simulation`           |
| `n`         | 생략하면 7, 유한 숫자는 정수 절삭 후 2~100으로 보정, 비유한 값은 7 |
| `algorithm` | `divide-half` 외에는 `sequential-pair`                             |
| `placement` | `random` 외에는 `worst`                                            |

숫자 입력 컨트롤은 Enter/blur 때 값을 확정하며 빈 값이나 0은 7로 처리한 후 범위를 제한합니다. URL의 빈 문자열은 숫자 변환 결과 0이므로 2로 제한됩니다. 화면이 잘못된 쿼리를 해석해 보정하더라도 모든 값을 즉시 URL에 다시 쓰는 것은 아닙니다.

모드 변경은 브라우저 이력에 추가하고 다른 설정은 `replace`로 갱신합니다. 진행 상태·runId·가짜 동전의 실제 위치·실험 기록은 URL에 저장하지 않습니다.

### 실험 기록 저장

[state/records.ts](../../src/simulators/balance-scale/state/records.ts)의 `Experiment` 필드:

| 필드            | 의미                                      |
| --------------- | ----------------------------------------- |
| `id`            | `runId:algorithm` 형식의 중복 방지 식별자 |
| `n`             | 동전 수                                   |
| `algorithm`     | 알고리즘 ID                               |
| `fakePlacement` | `worst` 또는 `random`                     |
| `fakeIndex`     | 가짜 동전의 0 기반 위치                   |
| `comparisons`   | 실제 저울질 횟수                          |

저장 키는 `computer-lab.balance-scale.v1`입니다. 각 알고리즘이 완료될 때 저장하므로 비교 모드는 먼저 끝난 결과도 먼저 기록합니다. 실행 내부의 Set과 기존 기록의 ID 검사로 되감기 후 중복 저장을 막고 최근 500개만 유지합니다.

읽을 때 JSON 배열 여부, 필드 타입·허용값·범위를 검사합니다. 횟수 검증은 공통 범위 `1..floor(n/2)`이며 알고리즘별 상한이나 실제 재실행 결과까지 검증하지 않습니다. 손상된 JSON은 빈 배열로 처리하고 유효하지 않은 행은 제외합니다. 쓰기 실패 시 기록 탭에서 임시 저장 상태를 안내합니다. CSV 내보내기·기기 간 동기화는 없습니다.

[ComplexityChart.tsx](../../src/simulators/balance-scale/components/ComplexityChart.tsx)는 N=2~100의 정확한 최악 횟수 두 선과 알고리즘별 실험점을 그립니다. 선 패턴·점 모양·문구 범례로 구분하며 표가 실험점의 대체 정보를 제공합니다.
